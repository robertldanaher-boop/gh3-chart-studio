# MSIX and code signing — Windows developer steps

MSIX is the primary new binary packaging path. It contains one x64 desktop app
package in a .msixbundle, with a self-contained Python 3.11/Qt/audio runtime. It
uses Windows installation/uninstallation, not the Python/pip bootstrap installer.
The existing Inno installer remains a source-install fallback.

MSIX sideloading requires a signature trusted on the destination device. Packaging
alone is not a Defender clearance, Microsoft Store approval or signing identity.
No production certificate/private key is supplied or generated by this project.

## Local Windows prerequisites

- Windows 10 1809+ / Windows 11 x64; Python 3.11 x64 and requirements-dev.txt.
- Windows 10/11 SDK, including MakeAppx.exe and SignTool.exe. The scripts discover
  x64 tools under Windows Kits/10/bin; optional GH3_MAKEAPPX_PATH and
  GH3_SIGNTOOL_PATH overrides accept exact executable paths.
- A code-signing certificate with an accessible private key and Code Signing EKU
  in CurrentUser/Personal (Cert:\CurrentUser\My). Hardware/cloud key providers may
  work through their installed Windows provider; provider setup is external.
- Inno Setup 6.3+ only if also building the fallback installer.

Use the real CA/service-issued identity for distribution. The certificate Subject
becomes the exact MSIX manifest Publisher. Keep it stable across updates. The
package identity is BobDanaher.GH3ChartStudio, Application Id Studio. The current
x64 version is the app's major.minor.patch plus .0 (for example 0.20.0.0).
A Microsoft Store submission would need the Store-assigned identity/publisher and
separate Partner Center validation; this does not reserve a Store identity.

## Build a signed bundle

In PowerShell from the complete repository checkout, after installing requirements:

```powershell
$env:GH3_SIGNING_THUMBPRINT = 'YOUR_CERTIFICATE_THUMBPRINT_FROM_CERTIFICATE_DETAILS'
.\packaging\BUILD_MSIX.cmd
```

The thumbprint is a public certificate identifier, not a password. No PFX password
is passed to SignTool. The builder:

1. Builds the onedir executable with existing PyInstaller dependencies and no UPX.
2. Generates icons/manifest, with the certificate's Subject as Publisher.
3. Signs the app executable using SHA-256 and an RFC3161 timestamp.
4. Runs the actual frozen program's Qt/assets, 1,000-note chart/MIDI read-back,
   Ogg codec and bundled FFmpeg smoke checks. These do not prove audible playback.
5. Runs MakeAppx pack and bundle with normal SDK validation enabled (no /nv).
6. Signs the bundle and verifies signature trust, expected signer and timestamp.
7. Records signature reports, bundle SHA-256 and the native binary inventory.

Output: packaging/output/GH3ChartStudio-VERSION-x64.msixbundle and JSON reports.
No unsigned fallback is allowed on a signed build. Signing failures stop the build.
The default RFC3161 server is http://timestamp.digicert.com; sign.ps1 also accepts
an explicit -TimestampUrl for another RFC3161 service. Timestamp responses are
cryptographically verified; availability of the external service is required.

For a local engineering-only build without an identity:

```powershell
.\packaging\BUILD_MSIX.cmd -Unsigned
```

Its .unsigned.msixbundle is marked unsigned and is not a normal installable
release. Do not distribute a test certificate as a publicly trusted publisher.

## Fallback EXE signing

```powershell
.\installer\build_installer.cmd
```

Signed by default; Inno's SignTool hook signs the installer and applicable internal
self-copies, then the final EXE is verified. Use -Unsigned only for a development
EXE whose filename ends -unsigned.exe. Direct ISCC builds must explicitly define a
signed or unsigned build; the template cannot silently create an anonymous release.
The older build_windows.cmd also signs its frozen app by default; -Unsigned is an
explicit developer-only opt-out.

## GitHub release configuration

Before adding secrets, configure the GitHub environment **windows-release** with
appropriate approval/protection rules. The code does not configure those rules or
purchase/issue a certificate. Store credentials only in GitHub/environment secrets,
never in the repository or chat:

- GH3_CODESIGN_PFX_BASE64 — importable PFX bytes encoded as base64.
- GH3_CODESIGN_PFX_PASSWORD — PFX password.
- GH3_CODESIGN_THUMBPRINT — exact expected signing certificate thumbprint.

The hosted-runner path supports an existing importable PFX. Many modern public
code-signing credentials use non-exportable hardware/cloud keys; do not assume
those can be exported as PFX. Use the local certificate-store build with the
provider installed, or arrange a suitable signing runner/provider integration.

The importer uses a temporary file outside the source/payload, imports the key
without printing its password, pins its thumbprint and removes the PFX. A final
workflow cleanup removes the imported identity/private key. PFX/key file patterns
are excluded from Git and from fallback installer payloads.

A production MSIX release also requires the environment variable/repository variable
GH3_BINARY_REDISTRIBUTION_REVIEWED=true, set only after arranging the matching
source/notices/relinking materials required by the actual bundled Qt, FFmpeg and
other native libraries. Existing notices alone are not that review. This variable
records the distributor's decision; it is not a legal compliance certification.
See THIRD_PARTY.md and docs/FFMPEG_DEPENDENCY.md.

PR/manual CI builds an unsigned engineering bundle, exercises the frozen app and
SDK packaging, and uploads validation JSON only for the MSIX path. It does not
publish the self-contained runtime before the native dependency review. It can
upload the explicitly unsigned source-install fallback EXE, which does not embed
Qt/FFmpeg runtime binaries. A published release must have a tag matching the app
version; missing credentials, invalid signatures or missing redistribution review
stop binary publication. Only the verified MSIX bundle is attached as the primary
release package. No release has been published by adding these scripts.

## Test installation and updating on Windows

After a real signed build and redistribution review:

1. Verify Properties → Digital Signatures and the expected publisher, or run
   installer/sign.ps1 -Path PATH_TO_BUNDLE -VerifyOnly with the expected thumbprint.
2. On a clean Windows 10/11 x64 VM, double-click the bundle or use
   Add-AppxPackage -Path .\GH3ChartStudio-VERSION-x64.msixbundle.
3. Launch from Start. No Python/pip installation should run. Confirm the first-run
   notice, Home, both song goals, audio preview and four-fret export work.
4. Check settings/pattern cache are writable in user data, with no package-directory
   writes. Export charts to a separate user folder and confirm no Medium Orange.
5. About → Check for updates must explain Windows-managed updating; no source ZIP
   or Win32 installer may replace the package. Startup source-update checks are off.
6. Install a higher four-part version with the same identity/publisher. Verify
   user state/exports, then test Settings → Apps uninstall in the VM.
7. Test a real song in TheGHOST and Dolphin separately. Structural/signature checks
   do not establish game compatibility.

Automatic .appinstaller hosting/update feeds and Store publication are not added.
Install newer signed bundles through Windows for now. The classic and MSIX installs
can coexist; remove the classic install only after verifying the new one. MSIX
uninstall removes package-managed state; keep songs/exports outside that state.

## Evidence and limits

Read M20_TEST_RESULTS.txt and the PR's latest Windows job for executed checks.
Native integration tests use an isolated self-signed test identity, temporarily
trusted inside the CI runner, to test real SDK signing, timestamps, tamper rejection
and bundle/installer construction. They remove it afterwards. That test identity
is not a production publisher and is never uploaded.

Actual sideload/upgrade/uninstall and public publisher trust require a configured
identity and manual Windows acceptance. A successful compilation or local test
signature must not be described as a warning-free, Store-approved release.
